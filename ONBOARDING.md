# ONBOARDING.md — How to Use the [PLACEHOLDER] Markers

This workspace is a template. Several files contain `[PLACEHOLDER: ...]` markers instead of real information — each one tells you what's missing and, in most cases, the question to ask to get it.

## The rule

**If you see any `[PLACEHOLDER]` in USER.md, this is a new deployment.** Before doing any research, analysis, or recommendations, work through the placeholders with the person you're working with. Do this as a natural conversation, not a form — ask one question or a small cluster at a time, and let their answers guide follow-ups.

Open with something like:

> "Before I start doing any research, I want to get to know you and how you invest — a few questions, take as long as you like. Nothing here is required beyond the basics; you can skip anything you're not comfortable sharing and we can fill it in later."

## How to work through it

1. Go file by file — **USER.md first**, then **state/constraints.md**, then **state/watchlist.md**, then **MEMORY.md** and the rest. Each placeholder has a suggested question next to it.
2. Ask naturally — use the questions as a guide, not a script to read verbatim.
3. Write the answers directly into the files, replacing each `[PLACEHOLDER: ...]` with the real content.
4. Where a placeholder says a section is optional (financial detail, sector interests), say so plainly BEFORE asking — never make someone feel they must answer.
5. **Before finishing, ask one last open question:** "Is there anything else about you, your goals, or how you'd like me to work that I haven't asked about?" This is the catch-all — some things people only volunteer when given an open lane, not a specific question. Add whatever comes up to USER.md, or wherever it fits best.
6. **Show the person what you wrote** — the actual filled sections — and ask "does this look right?" Only remove the last markers after they confirm.

## What NOT to do

- Do not make any investment recommendations until this is done.
- Do not fabricate or guess an answer to fill a gap — leave it genuinely blank and say so, rather than inventing detail.
- Do not pressure toward sharing more financial detail than someone offers — light and heavy are equally valid starting points (see MEMORY.md).
- Do not silently change SOUL.md or MONITORING.md if someone wants a different working style than the picker default — flag it and confirm with them before editing files that define core behavior.

Once every `[PLACEHOLDER]` is resolved and confirmed, proceed to normal operation per MONITORING.md.
